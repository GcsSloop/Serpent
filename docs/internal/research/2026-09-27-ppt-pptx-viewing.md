# PPT 与 PPTX 查看方案

> 日期：2026-09-27
> 工单：`Serpent-a15f51`（P2）
> 范围：能逐页看。不需要动画、切换效果或讲演者视图。本文件只记录方案，不实现查看器。

## 结论

不要在渲染进程里解析 PowerPoint 的绘图模型。第一版把 `ppt` / `pptx` 转成 PDF，再复用现有 PDF 查看器。PDF 页是静态的，动画自然不在范围内。

这条路和 DOC/DOCX 的评估一致：隔离的媒体进程调用 LibreOffice headless，`--convert-to pdf`，成功后走 PDF.js 的页面渲染和首页缩略图。见 `docs/internal/research/2026-09-25-flv-ai-word-preview-feasibility.md`。

## 两种容器

| 扩展名 | 容器 | 直接解析的代价 |
| --- | --- | --- |
| pptx | ZIP，内含 OOXML 幻灯片、主题和媒体 | 要自己排版 DrawingML。文本框可以抽出来，版式、字体、图表和组合形状对不齐。 |
| ppt | OLE 复合文档 | 比 pptx 更不适合自研解析。 |

LibreOffice Impress 对这两种都能尝试转 PDF。转失败的文件保持「不支持内置预览」，并保留用外部应用打开。不要把扩展名识别写成已经能看。

## 建议接法

1. 格式注册把 `ppt` / `pptx` 标成 document，但预览能力取决于转换是否成功。
2. Worker 在临时目录里转换。开始前检查目标盘空间；成功、失败或进程退出都要删掉临时 PDF。不要把转换结果留在系统盘上不回收。
3. 转换结果只作为预览衍生物。源文件仍是原来的 ppt/pptx。
4. 查看器用现有 PDF 翻页，不新做幻灯片 UI。
5. 缩略图用首页，沿用 PDF 缩略图。
6. 动画、音视频、切换、备注讲演视图都不做。备注若出现在 PDF 里是转换器的副作用，不单独做备注栏。

## 代价

- 要捆绑或发现 LibreOffice。安装包体积、启动时间和许可证清单都要单独算。LibreOffice 是 MPL 2.0，分发前要盘点实际打包的第三方组件。
- 字体缺失时版式会变。这是转换保真问题，不是查看器 bug。
- 加密或损坏的文件会失败，界面用现有的无预览状态。
- 很大的演示文稿转换会久。要有进度，并允许取消；取消后清临时文件。

## 不做的替代

- 只解压 pptx 里的 `ppt/media` 图片。那不是幻灯片。
- 在界面里嵌远程 Office 预览。
- 用浏览器打开原文件。Chromium 不渲染 ppt/pptx。

## 验收（实现时）

- 一份多页 pptx 能逐页看到画面，图片 `complete && naturalWidth > 0` 或 PDF 页有非零尺寸。
- 一份 ppt 同样能看，或明确失败为无预览。
- 没有动画控件。
- 转换失败和取消都不留下临时目录。
- 普通图片和 PDF 的查看不变。
