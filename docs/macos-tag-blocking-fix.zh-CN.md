# macOS 连续标签修改阻塞：复现、修复与验证

版本：0.2.10-macos.3。日期：2026-10-06。

## 复现结果

使用真实资源库的独立副本及原 iCloud 引用素材测试，保留真实文件类型、目录结构、缩略图任务和下载状态；操作只写入副本。资源库有 7,199 项，其中主要引用范围 7,152 项；默认忽略规则使实际浏览范围略小。

旧版 0.2.10-macos.2 的路径：打开引用目录 → 选中文件 → 在右侧创建并应用标签 → 首次约 509 毫秒显示成功 → 等待 3.5 秒 → 再次创建并应用标签 → 切到所有资产。第二次创建标签和新目录的浏览请求都没有返回；等待目录 20.3 秒后，卡片仍保留旧目录内容，第二个标签仍未显示。

此前仅使用小型合成 PNG、直接调用标签 API 的对照未能触发此故障。这次通过真实界面及真实媒体副本复现，不能再把结论停留在“存在调度风险”。

## 根因

PDF 缩略图的 pdfjs 解析、图片解码及 canvas 绘制原本运行在拥有 SQLite 和 IPC 调度的 Library Worker 线程。代码中的 await 不能让同步计算离开这个线程。性能记录中能看到 PDF 图片处理函数 `#getLinearizedBlockData`、`_convertYccToRgb`、`quantizeAndInverse`，以及打包 PDF 绘制代码占用 CPU；系统采样也显示该线程持续运行 JIT/绘制调用。

线程被占用时，第二次标签请求已到达主进程，但 Worker 不能及时收取、调度和回复请求，目录切换也被一起挡住。首个标签之所以快，是因为它在重计算开始前完成。

每次标签关系变化又发送普通 asset.changed：Renderer 清空缩略图状态、在 300 毫秒后重载整个目录及封面；Worker 同时清除可见窗口身份。一个文件的标签改动因此会扩大成浏览/封面工作，放大后台重计算的影响。

普通修改还需等待全部调度持有者结束，且新的浏览请求可以持续插队；旧目录分页响应缺少及时的代次校验。这两项会进一步延后修改或引发无效查询，随本次一起修复。

该阻塞在数据库位于本机磁盘、素材仍引用 iCloud 的副本中也复现。因此 iCloud 数据库位置不是这个已复现故障的必要条件。iCloud 仍可能增加文件协调或提交耗时，但本次确定的主要阻塞来自同线程 PDF 重计算与过度刷新。

## 修复

1. PDF/兼容 AI 的读取、解析、首屏绘制和 JPEG 编码进入独立 Node Worker 线程；数据库登记仍由原 Library Worker 完成。跨资源库同时最多一个 PDF 解码；单次 30 秒超时，可通过 AbortSignal 终止，关闭应用会回收线程。先等待线程退出再清理输出，避免取消后留下继续写入的线程或半成品。取消不登记为永久缩略图失败。
2. 保留 pdfjs 原始模块入口及资源路径，避免将它打包进数据库线程时破坏 import.meta.url；标准字体、CMap 与 WASM 使用 Node 文件读取路径。记录实际 JPEG 尺寸。
3. 标签变更带有 tags 语义提示。普通目录只刷新标签列表和所选资产元数据，保留缩略图/窗口缓存；文本搜索、标签筛选和智能合集仍重新查询，保证匹配结果正确。
4. 修改已排队后不再放行新的浏览请求抢占下一个安全执行机会；继续保持修改独占 SQLite 的约束。
5. 每次分页等待返回后，先校验目录代次，再处理过期会话/回退查询；旧请求的清理不能删除新目录的正在加载标记。
6. Inspector 通过真实异步操作完成状态显示“正在保存标签…”，支持连续提交；保存状态按所选资产集合隔离，最终成功或失败仍由原通知处理。

## 相同路径复测

| 场景 | 结果 |
| --- | --- |
| 旧版、本机数据库＋真实 iCloud 素材 | 首次约 0.51 秒；第二次标签与切目录超过 20 秒仍未完成 |
| 新版、资源库副本也位于 iCloud、同一路径 | 第二次标签正常保存，100 毫秒采样估计约 178 毫秒显示；新目录请求完成及界面确认约 515 毫秒 |
| 新版、iCloud 副本、连续 12 次修改 | 同一文件、另一文件、延时再改，以及滚动到 85% / 40% / 95% 区域后连续修改均成功 |
| 上述连续操作的界面耗时 | 11 次等待标签显示的样本约 413–809 毫秒；另一次故意不等待返回，随后核对持久化 |
| 上述连续操作后切目录 | 约 467 毫秒；实际内容已切换 |
| 持久化核对 | 12 条测试标签关系全部存在于副本数据库 |

界面耗时包含点击、输入和标签出现；178 毫秒为定期界面采样估计，不能当作精密性能基准。上述数值是这组真实素材及缓存条件的测量，不代表所有文件或存储状态。

176 项相关单元测试、99 项 Worker 回归测试、2 项打包程序交互测试通过。覆盖 CPU 解码期间控制线程响应、取消/超时/关闭、PDF 缩略图、标签通知语义、写入历史、修改公平性、分页竞态，以及保存反馈、连续新增/移除标签、空格预览、名称原位编辑、递归目录与重启恢复。类型检查通过；相关代码检查无错误，保留 2 项上游既有 Hooks 警告。

打包门禁、原生组件检查、应用临时签名验证、DMG 完整性验证通过，版本 plist 为 0.2.10-macos.3。独立 iCloud 测试副本在持久化核对后已清理。
