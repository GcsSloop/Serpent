# macOS 本地 AI 连接修复与验证

版本：0.2.10-macos.4。日期：2026-10-07。
测试服务：http://127.0.0.1:1234/v1。
测试模型：gcssloop/qwen3.8-27b-uncensored。

## 原因

服务本身可访问，Responses 和 Chat Completions 协议均可响应。
旧实现的连接检测需要经过 Library Worker 的后台队列，Main 的 15 秒期限包含排队时间；后台资源库任务或模型分析忙时，检测可能尚未发出就超时。旧日志记录过连接检测排队约 283 秒。这是历史调度故障的证据，不表示当前 Qwen 模型始终要等同样时间。

窗口重新获得焦点、每分钟心跳和手动测试会更新同一连接状态，没有统一阻止重叠或拒绝过期结果；一次短暂检测失败还会禁用分析入口。

本地服务通常不启用鉴权，程序却强制读取保存的密钥。实际日志包含密钥读取/解密失败；最终打包的冷启动复测进一步捕获到主线程停在 SecItemCopyMatching → SecKeychainItemCopyContent → SecurityServer decrypt 等 macOS 钥匙串调用中。因此，仅在解密抛错后捕获异常仍不够：同步调用可以在抛错前长时间阻塞整个主线程。采样证据保存在 out/diagnostics/local-ai/startup-main-sample.txt。

模型默认开启思考；只限制很少输出 token 的文本探测可能只返回思考内容，HTTP 200 并不能证明已生成最终答案。此前 Bonsai 图片探测耗时 45.7 秒仍没有最终答案；指定 Qwen 模型在关闭思考的直接图片请求中约 5.2 秒返回有效 JSON。

## 程序修改

- Main 独立负责网络连接检测，不占用 Library Worker 队列。手动测试验证模型实际产生最终文本，允许冷加载模型使用最多 120 秒；本地心跳以 10 秒期限检查模型列表，不发起重复推理。
- 相同的检测请求在 Main 合并。界面使用请求代次和在途标记，手动检测优先，旧检测结果不能覆盖新结果；编辑 AI 设置期间暂停保存配置的心跳。
- 检测状态用于反馈，短暂心跳失败不会阻止用户主动启动分析。真正的分析错误仍由作业状态反馈。
- 显式 HTTP(S) 回环地址的 OpenAI 服务支持空密钥。先通过无鉴权请求异步检查服务：只有明确返回 401/403 时才读取保存的密钥；服务不要求鉴权、不可达或未提供 models 接口时都不会触碰钥匙串。显式输入的密钥仍优先使用，无密钥时不发送空的 Authorization。启用服务鉴权时仍可填写并保存真实密钥；远程服务仍要求密钥，切换到远程地址会重新检查凭据。
- 模型名称加载、保存和发送时去除首尾空格。私有 Main/Worker 协议仅对本地 OpenAI 地址允许空密钥。
- 新增“思考模式”：自动、使用服务默认设置、关闭思考。自动模式对本地 OpenAI 分析关闭思考，采用 2048 token 输出预算；云端自动模式保留服务默认行为。不支持思考参数的服务仅在明确拒绝该参数时退回默认请求，不掩盖错误模型、错误图片或其它 HTTP 错误。
- 本地 OpenAI 并发限制为 1–2，旧配置中的 16 会按 2 加载并在保存时持久化，界面显示对应说明。远程服务仍支持原来的并发范围。
- 本地 AI 搜索规划也使用空密钥和关闭思考的兼容设置。

## 验证

在打包应用中创建独立的临时资源库与用户配置，模拟已有但无法解密的密钥，配置指定模型并留空 API Key。
通过真实设置界面保存，连续两次手动测试连接，再通过右键菜单依次分析 red.png、green.png、red.png。
每次分析过程中同时调用三次本地连接检查并触发窗口焦点心跳，核对作业完成以及描述、标签、评分和模型名称的持久化结果。
首次打包验收中三次分析约 9.98、8.89、9.94 秒；并行连接检查约 2.5、5.4、4.1 毫秒。时间包含模型推理、结果保存和轮询发现完成，不是纯模型速度。
最终产物重新验证：red.png：分析 6.89 秒，连接检查 4.10 毫秒；green.png：分析 5.86 秒，连接检查 5.80 毫秒；red.png：分析 7.88 秒，连接检查 4.20 毫秒。两次冷启动正常，检测到的密钥解密调用数为 0。5 项打包验收通过，Windows 专用测试跳过；完整结果保存在 out/diagnostics/local-ai/qwen-packaged-acceptance-final.json。

181 项相关单元测试、91 项 AI Worker 集成回归通过。打包应用的实际导入、FTS5 搜索、空格预览开关、名称原位编辑和连续标签修改回归通过。类型检查通过；代码检查没有新增错误，保留 App.tsx 中两项既有依赖警告。

验收最初使用过期的设置页标签名称，现已匹配“AI分析”页签并等待页面加载。后续初始界面等待、截屏和退出超时并非都属于脚本问题：主线程采样明确定位到同步钥匙串读取。修复后必须重新执行冷启动和真实分析验收，尚未执行的分析不计为成功。

测试使用合成图片，不改动用户真实资源库、现有配置或安装在 /Applications 中的应用；没有进行大量并发压力测试。指定模型在此 LM Studio 服务已验证支持 reasoning.effort=none。
